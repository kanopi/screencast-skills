## [Unreleased]

### Added

- **Method A browser engine** (`browser-scene.sh` + `browser-scene.mjs`) — the
  recommended way to record docs/UI tours. Playwright renders the page headless
  at 1920x1080 and records **only the page**: no OS screen capture, no
  Screen-Recording permission, no cursor calibration, no Retina scaling, and no
  risk of leaking other windows. Spec-driven (URL + `steps`: scroll / highlight /
  wait), waits for `document.fonts.ready` to avoid FOUT, `deviceScaleFactor: 2`
  for crisp text.
- **Method B automation** (`browser-scene-screencap.sh` + `.mjs`) — drives a
  headed fullscreen Chromium while ffmpeg avfoundation captures the screen, then
  scales to 1080p, with runtime auto-detection of the "Capture screen 0"
  avfoundation index (indices shift as cameras connect/disconnect). For the real
  on-camera cursor only; carries a screen-leak caution.
- `narrate.sh` — pluggable TTS: narration can be generated by **ElevenLabs**
  (`awaz` + `ELEVENLABS_API_KEY`) or **OpenAI** (`OPENAI_API_KEY` + `jq`,
  `POST /v1/audio/speech`, `instructions` supported; voices incl. `marin`/`cedar`).
  Engine chosen by `TUT_TTS` or whichever key is set; voice via `TUT_VOICE`.
  Replaces the direct `awaz` call in the workflow.

### Fixed

- **Audio distortion across scenes** — `concat.sh` now uses the concat *filter*
  (decode → join → single encode) instead of the concat demuxer, which left AAC
  encoder-delay gaps at every boundary that accumulated into audible distortion;
  `finish-scene.sh`'s silent track is now mono to match narration so the filter
  concatenates uniformly.
- `browser.mjs` / `browser-scene.mjs` resolve the globally-installed Playwright
  via `createRequire` (ESM `import` ignores `NODE_PATH`).
- `lib.sh` now honors an exported `HDIR`, so the `.sh` scripts and
  `browser-scene.mjs` agree on the build dir regardless of working directory
  (previously the intro could land in the wrong folder).
- `render-tape.sh` now runs vhs from inside the build dir with relative paths, so
  an absolute `TUT_BUILD_DIR` works (VHS's parser rejects an absolute `Output`
  path).
- ffmpeg auto-detection prefers a drawtext-capable build (keg-only `ffmpeg-full`)
  since Homebrew's plain `ffmpeg` omits libfreetype; `make-card.sh`/
  `still-scene.sh` now log and fail loudly instead of hiding ffmpeg errors; the
  mono-font download URL was corrected (Roboto Mono).

## [1.0.0] - 2026-07-22

### Added

- **`screencast-storyboard`** skill — authors a tutorial script from a goal.
  Reads the tool's real README / install command / config JSON so the
  transcript's commands and config are accurate, drafts
  `.tutorial-build/<slug>/storyboard.md` (scenes with type, on-screen actions,
  narration, one-line caption, pacing), presents `STORYBOARD READY FOR
  APPROVAL`, and stops for a subsequent-message approval. Never fabricates
  config or commands. Anti-rationalization table + red-flag list citing CANT
  IDs. Dependency-free. `agents/openai.yaml`: `allow_implicit_invocation: true`.
- **`screencast-tutorial-video`** skill — produces a narrated, captioned
  1920x1080 MP4 from an approved storyboard on the macOS host. One engine per
  surface: VHS `.tape` for terminals, ffmpeg `zoompan`/`drawbox` still-motion
  for native apps, Playwright (locate) + cliclick (visible cursor) + ffmpeg
  avfoundation (capture) for the browser, command cards for abstract commands.
  Ported the `finish-scene.sh` pad-to-narration + caption bar, `concat.sh`, and
  `make-card.sh` ffmpeg pipeline from `drupal-tutorial-video` off the ddev
  container onto the host. ElevenLabs voice-over via `awaz`. Reports real
  preflight failures; never claims an unproduced video; never cleans up the
  build dir. `agents/openai.yaml`: `allow_implicit_invocation: false`.
- Routing eval prompts differentiating the authoring scope ("script / draft /
  outline") from the production scope ("record / produce / render").
- Behavioral eval cases: storyboard gate, storyboard pressure (CANT-1/CANT-6),
  storyboard no-fabrication (CANT-3), and video honesty. Fixtures:
  `mock-mcp-tool` (real README + config so "read the source" succeeds) and the
  template's `plain-git-repo` (no docs).
- Scaffolded from the Kanopi skills-plugin-template. Prior art:
  `kanopi/drupal-skills`' `drupal-tutorial-video` skill.
